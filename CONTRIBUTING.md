# Contributing to Awesome Browser

Thank you for helping build a high-quality curated list of browser-related tools and resources.

## Curation Rules

An entry may be added only if it satisfies most of these criteria:

1. **Clear official source** — Has a clear official website, repository, or store page.
2. **Verifiable maintenance** — Its maintenance status can be checked from public information.
3. **License or pricing clarity** — The license or pricing model is clearly stated and verifiable.
4. **Concrete browser-related use case** — It has a specific, practical use case connected to browsers.
5. **Safe and trustworthy** — It is not malware, spyware, or obviously deceptive.
6. **Differentiated** — It is not only a thin clone with no clear differentiator from existing entries.
7. **Verifiable description** — The description can be confirmed from public information.
8. **Adds value** — The entry meaningfully expands the list rather than creating noise.

### Stricter Rules for Browser Extensions

1. Prefer open-source extensions.
2. Prefer extensions with a known maintainer or organization.
3. Avoid abandoned extensions that require broad permissions.
4. Avoid extensions with a history of privacy abuse unless listed in the archived/historical section with a clear caveat.
5. Consider requested permissions and their necessity for the extension's claimed purpose.

## Entry Format

All entries must follow this format:

```
- [Name](URL) - Clear, non-marketing description.
  `License/Pricing` `Engine/Platform` `Status` `Best for`
```

**Rules for descriptions:**
- Be factual and concise.
- Avoid hype words like "powerful", "best", "ultimate", "revolutionary", "awesome".
- Use consistent tags from the controlled vocabulary (see below).
- Prefer official website or official repository URLs.
- For extensions, prefer the official store page with source repository link where available.
- Mark archived or unmaintained projects clearly with the `Archived` tag and a note.

## How to Contribute

### Adding a New Entry

1. Open an issue using the **Add Entry** template.
2. Fill in all required fields: name, URL, category, description, license/pricing, and reason for inclusion.
3. Wait for feedback or open a pull request directly.

### Reporting a Dead Link or Outdated Entry

1. Open an issue using the **Report Dead Link / Outdated Entry** template.
2. Provide the entry name, current URL, and the problem type.
3. Include a suggested fix or reference if available.

### Submitting a Pull Request

1. Fork the repository and create a branch.
2. Add your entry to the appropriate category in `README.md`.
3. Follow the entry format exactly.
4. Complete the pull request checklist.
5. Ensure all links in your submission are valid.
6. Submit the PR and respond to any review feedback.

## Quality Expectations

- **No marketing language** — Descriptions should be objective and factual.
- **No placeholder text** — Every field must be complete.
- **No dead links** — Verify all URLs before submitting.
- **No duplicate entries** — Check that your entry is not already listed under a different name.
- **Correct category** — Place entries in the most specific applicable category.
- **Archived projects** — Must be clearly marked and placed in the Unmaintained/Archived/Historical section unless they serve a continuing educational or reference purpose.

## Maintenance

The maintainers periodically:

- Run automated link checks.
- Review entries for continued maintenance status.
- Update license and pricing information.
- Clean up abandoned or dead entries.
- Evaluate and merge community contributions.

Check the repository issues for tasks labeled `good first issue` to find easy ways to contribute.
